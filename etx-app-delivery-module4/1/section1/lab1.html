Lab 1: Install and Configure RHDH

In this lab, you’ll install Red Hat Developer Hub on OpenShift and deploy a minimal portal configuration that will serve as the foundation for the remaining exercises in this module.

By the end of this lab, you will have:

  • Installed the Red Hat Developer Hub Operator

  • Created a minimal Developer Hub application configuration

  • Deployed a Red Hat Developer Hub instance

  • Verified that you can access and sign in to the portal

Install the Red Hat Developer Hub Operator

  1. Get the OpenShift web console URL from your RHDP lab environment page and open in the browser.

  2. Sign in using the admin credentials provided on the RHDP Lab Environment page.

  3. From the navigation menu, select Ecosystem → Software Catalog.

    Figure 1. Ecosystem → Software Catalog(Click the image to view it in full size in a new browser tab)

  4. Search for Red Hat Developer Hub.

    Figure 2. Red Hat Developer Hub Operator(Click the image to view it in full size in a new browser tab)
    It may take a few moments for OperatorHub to finish loading all available operators.

  5. Select the operator and click Install.

    Figure 3. Install Red Hat OpenShift Hub Operator(Click the image to view it in full size in a new browser tab)

  6. Accept the following installation settings:

    • Installation namespace: rhdh-operator

    • Installation mode: All namespaces

    • Approval strategy: Automatic

  7. Click Install.

  8. Wait until the operator status changes to Succeeded.

    Figure 4. Red Hat OpenShift Developer Hub Installed(Click the image to view it in full size in a new browser tab)

Create the Developer Hub Project

Deploy Red Hat Developer Hub into a dedicated OpenShift project.

oc create namespace setup-rhdh

Verify the project was created successfully.

oc get namespace setup-rhdh

The output should include the setup-rhdh namespace.

Create the Application Configuration

Red Hat Developer Hub loads its application settings from an app-config.yaml file. For this training, you’ll provide the configuration using a Kubernetes ConfigMap.

  1. Copy the output of the following command. This value is the openshift_cluster_ingress_domain and is required in the next step.

    oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}{"\n"}'

  2. Apply the following manifest, replacing {openshift_cluster_ingress_domain} with the value obtained from the previous command.

    oc apply -f - <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: rhdh-config
  namespace: setup-rhdh
data:
  app-config.yaml: |
    app:
      title: Red Hat Developer Hub
    backend:
      reading:
        allow:
          - host: 'gitlab.{openshift_cluster_ingress_domain}'
    auth:
      providers:
        guest:
          dangerouslyAllowOutsideDevelopment: true
EOF
    The backend.reading.allow setting allows Red Hat Developer Hub to retrieve Software Catalog information and Software Templates from the GitLab instance used throughout this training.
    Guest authentication (dangerouslyAllowOutsideDevelopment) is intended only for development and training environments. Production deployments should integrate with an enterprise identity provider such as Red Hat Build of Keycloak.

Verify the ConfigMap

Verify that the ConfigMap was created successfully.

oc get configmap rhdh-config -n setup-rhdh

The output should include the rhdh-config ConfigMap.

Deploy Red Hat Developer Hub

The Red Hat Developer Hub Operator watches for Backstage custom resources and automatically provisions the application, database, routes, and supporting Kubernetes resources.

Apply the following manifest.

oc apply -f - <<'EOF'
apiVersion: rhdh.redhat.com/v1alpha5
kind: Backstage
metadata:
  name: rhdh
  namespace: setup-rhdh
spec:
  application:
    appConfig:
      mountPath: /opt/app-root/src
      configMaps:
        - name: rhdh-config
    route:
      enabled: true
  database:
    enableLocalDb: true
EOF

Verify the Deployment

Wait for the Developer Hub pods to become available.

oc get pods -n setup-rhdh -w

Verify that both pods are in the Running state, it might take couple of minutes.

The output should include pods similar to:

  • backstage-rhdh-xxxxxxxx

  • postgresql-xxxxxxxx

Next, verify that the Backstage custom resource was created.

oc get backstage -n setup-rhdh

s == Access Red Hat Developer Hub

Retrieve the Developer Hub route and open the route URL in your browser:

oc get route backstage-rhdh \
  -n setup-rhdh \
  -o jsonpath='https://{.spec.host}{"\n"}'

If you receive an Application is not available message, wait a minute for the pods to finish starting and refresh the page.

On the sign-in screen, select Guest and click Enter.

Figure 5. Sample Sign-in Screen (Click the image to view it in full size in a new browser tab)

After signing in, you should see the Red Hat Developer Hub home page.

Figure 6. RHDH Home Page (Click the image to view it in full size in a new browser tab)
